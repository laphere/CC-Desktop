2026-09-22 会话页可读性整改（`src/styles.css`）：正文字号 13.5→14.5、行内代码从高饱和蓝字改浅底 chip、h2/h3 加章节线、次要文字对比度补齐、表格加内边距。用户提需求时给的是「app 会话页 vs 系统终端 TUI vs 另一款浅底 agent」三组截图对照。

**Why:** 被否的两次都是我**自己加戏**的部分，不是他提的需求：① 我按排版理论把内容列限成固定 760px 居中 → 「太窄了，看着很别扭」，改 1000px 后他仍要求换成百分比（现为 `--read-width: 88%`，收起左栏跟着变宽）；② 我提议的「轮次锚点」（助手消息左侧竖线）→ 「不是一个好的设计」。他判「可读性」靠的是**密度 / 对比度 / 层级**，不是行长或装饰性分组 —— 轮次边界靠贴右的用户气泡本来就够。他完全接受终端 TUI 那种宽行。

**How to apply:** 再碰会话页、终端、面板这类阅读区时，只改他点名的东西，别按排版理论或设计惯例替他补方案；宽度类参数一律用相对值（百分比/跟随容器），不用固定像素。真要加观感增强，先给选项让他选，别直接落地。定稿参数见 `styles.css` 的 `--read-width` / `--rail-w`，注释里记了每次来回。

**另一条原则（2026-09-22 他明确纠正過我）：「和 TUI 一致 / 和参考截图一致」不是目标，可读性才是。** 他确实说过「TUI 里这些内容是蓝字无底」，但那是举例说明，不是让我把对齐本身当判据 —— 我当时据此把行内代码并成代码块的亮蓝（4.9:1，嵌在 14.3:1 的正文里会形成浅斑），被纠回「不一定非得和 TUI 一样」。取舍时按对比度/层级/密度选，别为对齐参照物牺牲它。
