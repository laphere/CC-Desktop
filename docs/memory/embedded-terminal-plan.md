架构：`src-tauri/src/pty.rs`（portable-pty/ConPTY，输出经 ipc Channel 二进制直传）+ 前端 `TerminalPane.tsx`（xterm.js）+ 内容区 tab 条（查看器与终端共用，App.tsx）。项目「+」新开会话、会话右键「继续对话」= `claude --resume <id>` 内嵌 tab。

**已验证**（CDP 驱动真 app 实测）：Channel 二进制+跨 chunk 中文、中文输入、TUI 渲染、关闭杀树零孤儿。**两个实测踩坑（改代码时勿回退）**：① Windows 击杀必须**先 `taskkill /T /F` 再 ChildKiller.kill**——反序会先孤儿化孙进程使 taskkill 找不到树，实测留 claude.exe+MCP 孤儿吃 API；② spawn 须剥 `CLAUDE_CODE_CHILD_SESSION`/`CLAUDE_CODE_ENTRYPOINT`/`CLAUDECODE` 环境变量——app 从 claude 会话终端里启动时子会话会继承，导致 transcript 不落盘、会话列表看不到。**真 IME 候选窗已定位并修复（2026-09-20，用户真机实测通过：新旧会话都不再出现）**：症状=候选窗不贴输入光标、流式输出时到处乱飘。根因两层：① **claude TUI 不用真光标画输入光标**（`?25l` 藏真光标 + 自画一格反显空格），而 Windows IME 只认真光标那格——实测差**整 10 格 + 1 行**（候选窗第 18 列/输入行下一行，claude 画的光标第 8 列/输入行，139px÷14=9.93）；② xterm 把 IME 锚点（`.xterm-helper-textarea`）按**逻辑光标**摆，`updateCompositionElements` 还挂 `onRender` 每帧重摆 → 空闲稳定错位、流式乱飘。**上游同样如此**（claude-code #29745/#35307、xterm.js #5734：WT / VS Code 集成终端一样中招）。修法在 `src/lib/ime-anchor.ts`（新增）：`findInputCaret` 在缓冲区**自底向上扫全部可视行**找「最下一格反显空格且左边有内容」= 光标格（**扫描窗不能只留底部几行**：新会话输入框在 logo 正下方的屏幕上方，实测 21 行终端里输入行第 6 行、状态行更低——第一版就是这么漏的），接管 xterm 两个私有定位方法钉在这一格；**两条实测踩过的闸**（先于"沿用上一格"生效）：只在 `coreService.isCursorHidden === true` 时接管（vim/nano 用真光标，其状态行整行反显空格会被误判）、扫不到时 3s 内沿用上一格；重算时机必须含 `onWriteParsed`（`?25l` 在输出末尾，缺它则 memo 把最后一次渲染挡掉、恰好差一格）。回归探针 `docs/ime-anchor-probe/`（真 Chromium 五步断言落点，"升级 xterm 后必跑"）；真输入法的观感仍需用户人工确认。

**贴图已修复并端到端实测**（2026-09-20，含三轮踩坑）：① 浏览器 paste 事件方案死路——xterm 里 Ctrl+V 走 WebView paste 只发文本，纯图片剪贴板一个字节都不发；② `\x16`（Ctrl+V 原始键码）在 Windows claude 2.1.278 实测**无反应**（PTY 探针逐键码验证）——**claude 的剪贴板粘贴绑在 Alt+V（`\x1bv`，ESC 紧跟 v 无空格；多一个空格就变成敲入空格+v）**，图片（位图）+文本通吃；③ **「复制的图片文件」另有一条独立通道**：cmd 里能贴是 conhost 在 Ctrl+V 时把文件路径当**文本**塞进输入流，claude 认出图片路径即转 `[Image #1]`——claude 自己读剪贴板的两条路都不认 CF_HDROP 文件列表。终局实现：TerminalPane 捕获 keydown（Ctrl+V/Cmd+V/Shift+Insert/Alt+V）→ 先问后端 `clipboard_image_path`（只读 CF_HDROP，取首个 png/jpg/jpeg/gif/webp）→ 有路径就 `term.paste(路径)` 当粘贴文本送进去，否则发 `\x1bv`（mac 发 `\x16`）。**别再改回「改写剪贴板」那一版**：会留下用户剪贴板被替换的副作用。三条路（图片文件/位图/纯文本）CDP 真机全部验过，图片文件那条还验了剪贴板保持不变。**调试方法论教训**：`window.__TAURI_INTERNALS__.invoke` 是 non-writable/non-configurable，**无法用赋值钩住**（静默失败、仪器全灭却报 hooked）——要用 CDP 先查 `getOwnPropertyDescriptor`；app 页面 Page.reload 会**泄漏全部 PTY**（React cleanup 在 unload 时不执行）→ 反复 reload 堆 claude 孤儿。**用户侧事实**：他在 cmd 里能贴图片文件（早期据此推翻了「claude 读不了」的错误结论）——遇到矛盾先信用户的实测。

**观感对齐系统终端两处已修**（2026-09-20，用户并排截图标定，详见 docs/embedded-terminal-plan.md 第六节）：① **粗体要更亮**——claude 发的是裸 `ESC[1m`（195 次，颜色走真彩色），cmd/WT 按 conhost intense 语义把「粗体+默认色」渲染成 brightWhite（实测 #F2F2F2），而 xterm 的 `drawBoldTextInBrightColors` 只管索引色 0-7、够不着默认色；新增 `src/lib/bold-bright.ts` 在 `term.write` 前做字节级流式改写补 `ESC[97m`/`ESC[39m`（真彩色粗体不动，否则灰粗体被冲白）。想与系统终端完全一致 → 把 `termTheme()` 的 brightWhite 改成 #f2f2f2。② **④ 显得特别小**——U+2460-24FF 圈号 Consolas 也有但画得极小（16.5×13.5 vs 中易黑体 24×22.5），而它排在 TermCJK 之前；styles.css 加两个 `unicode-range: U+2460-24FF` 的 @font-face（TermWide=SimHei、TermWide2=Segoe UI Symbol/125%，因为中易黑体只覆盖 50/160，缺 ⑪ 起）插在 Consolas 前。**换完字体还不够，还有第二刀**：claude 发的是 `**④ 回包后…**`（④ 后有空格）→ xterm 按 **1 格**算，满宽字形撞上 `rescaleOverlappingGlyphs` 被**横向压成 12×24 的细条**（用户第二次报"还是不对"就是它）→ 必须设 `rescaleOverlappingGlyphs: false`（系统终端是让它溢出格子）。**这个开关对块状字符本来就不生效**（阈值是字形宽 > 1.5 格 = 21 设备px，而 █ 只有 16.5px；开/关实测块状字符列剖面都是 0 处暗缝）——消缝靠整数字格宽 + WebGL，别把它当功臣。抓 claude 原始 PTY 流的探针**必须自己应答 DSR/DA/OSC 11**，否则卡在第一帧只吐 4 字节。**更正（2026-09-20）**：那首发 `ESC[6n` 不是 claude 发的，是 **cmd.exe/conhost 启动时**发的（spawn 后 21~30ms，早于 claude 的痕迹数百毫秒；纯 cmd.exe 不带 claude 照样发），**它没被应答 = 整条链（含 claude 启动）都不会发生**；应答晚 500ms 仍能完整恢复、不回则永久全黑。内嵌终端里这条应答由 xterm 生成、经 ptyIdRef 回灌，曾偶发被 `if (id !== null)` 吞掉 → 已修（pendingInput 排队 + `onSpawned` 提前交 id），详见 docs/embedded-terminal-plan.md §6.7。
