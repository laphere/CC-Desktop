会话级供应商 / 模型选择 · UI 方案

新会话在首条消息发送前可选供应商与模型；不选则完全跟随 ~/.claude/settings.json（全局当前供应商）。 选择按会话记录（session-providers.json），续聊复用；进程启动后供应商锁定，模型仍可在右侧热切。 下面帧内可点：点开下拉 → 选一个供应商/模型 → 点「发送」看锁定态。

模型

为什么必须在启动前选

供应商的 base URL 与凭证是 CLI 进程启动时构造 API 客户端用的，进程起来后改 env 不会重建连接。模型可以在会话内热切（setModel），但只能切到当前供应商映射的模型。

注入走 flag 层，不动全局配置

实测 settings.json 的 env 压过进程环境变量，而 SDK 的 --settings（flag 层）压过它。所以会话级供应商经 Options.settings.env 注入；凭证两键（AUTH_TOKEN/API_KEY）都写，避免逐键合并时全局残留赢。

不选 = 什么都不注入

chat_start 不带供应商/模型，CLI 按自身默认读 settings.json——与现在的行为完全一致。「记住上次选择」只影响下次新会话的默认预选。
